# out

A native macOS voice-input tool. Press Fn once to start recording, press it again to stop, and the text is written where the cursor is at that moment. It uses your own API key (OpenAI, Groq, SiliconFlow, or any service with an OpenAI-compatible API). SwiftUI + AppKit, no third-party runtime dependencies.

out is an independent implementation. It is not the official Typeless client and does not copy all of its features. It covers dictation, including editing existing text by voice; it does not answer questions, operate the computer or sync history to the cloud.

The interface is in English and Simplified Chinese (Settings → General → Language; "Follow macOS" picks Chinese when the first preferred language of macOS is Chinese).

## Install

On a Mac with macOS 14 or later (Apple silicon or Intel), one line in Terminal:

```sh
curl -fsSL https://raw.githubusercontent.com/subnsub-tools/subnsub-out/main/install.sh | sh
```

This is the only way to install out: there is no disk image or other installer. [`install.sh`](install.sh) reads `out.json` from the newest release (or from our site when GitHub cannot be reached), downloads the zip it names from that version's release and checks its size and SHA-256 against `out.json`, and that the app inside is out, of that version, signed with out's certificate; only then does it put the app in `/Applications/out.app` (in place of an older copy, and an old `input.app` goes to the Trash) and open it. Run it as yourself, not with sudo. A file that curl downloads carries no quarantine mark, so macOS does not stop the app's first launch; the script's checks stand in for that check. Run it again any time to bring out up to date by hand.

Then set it up as under [First use](#first-use): the service and API key in Settings (the gear at the right end of the panel's title row), and the Microphone and Accessibility permissions on the panel.

## Build and run

Requires macOS 14+ and the Swift 6 toolchain. The Command Line Tools are enough; a full Xcode is not needed. `build.sh` makes one app for Macs with Apple silicon and with Intel: it builds each architecture and joins them with `lipo`. The icon is `Resources/AppIcon.icns`, made from `Resources/AppIcon.svg` (Out! in Inter SemiBold, white on a dark ground) with `swift tools/icon.swift Resources/AppIcon.svg Resources/AppIcon.icns`.

```sh
bash build.sh --install
open /Applications/out.app
```

The app was first called Qingyan, then input, then put (until 0.1.49). The app name, process and install path are now out, and the menu bar item reads Out!; the bundle ID (`local.hopo.qingyan`), preferences, keychain items, history folder and Swift target names keep the first name, so existing permissions, API keys and history carry over. `--install` removes an old `/Applications/put.app`, `/Applications/input.app` or `/Applications/Qingyan.app`. A copy that an update from before a rename left at `/Applications/put.app` or `/Applications/input.app` moves itself to `/Applications/out.app` when it starts, and registers its login item again from there.

Quit out before installing. `build.sh` signs with the identity in `SIGNING_IDENTITY` and never falls back to an ad-hoc signature. `--install` copies the app to `/Applications/out.app` and registers it; without arguments the app is only built into `build/`. `INPUT_BUILD` sets the build number (the version becomes `0.1.<build>`).

macOS ties permissions (Accessibility, Microphone, Keychain) to the app's signing identity. As long as every build is signed with the same certificate and bundle ID, a new build keeps the permissions of the old one. Do not use a weak designated requirement that matches only the bundle ID to work around this, and do not edit the TCC database.

## First use

1. Open Settings (the gear at the right end of the panel's title row, or ⌘,). The services and keys are at the top: choose the service for recognition, enter its API key, click Save, then Verify. Text polishing is off: out enters the transcript as is, and a polishing service and its key are needed only once Text polishing is turned on there. Each service's key is stored separately, only in the macOS keychain, never in project files, logs, history or UserDefaults. A ChatGPT subscription does not include API credit. On macOS 26 and later, "This Mac" is offered for recognition as well: it uses the system's own model, so its audio never leaves the Mac and it needs no key.
2. The top of the panel lists the steps still missing; turn on the Microphone and Accessibility permissions there. The installed app adds itself to the permission lists. `open /Applications/out.app --args --setup-permissions` runs the first-time permission flow: Microphone first, then Accessibility. The system's confirmations must be given by the user.
3. Press Fn / 🌐 anywhere to start. Pauses do not stop the recording; press again to stop. Or hold Fn while you speak: the recording starts once it has been held on its own for about a third of a second, and stops when you let go. A key or a click within a second of that start means Fn was part of a key combination (Fn with an arrow or Delete, say), and that recording is dropped; one that comes later does not stop it. An F key or a key combination as the shortcut starts at once when pressed; held for a third of a second or more, its release stops the recording, and let go at once, it leaves the recording running until the next press. A Command key as the shortcut can only be tapped, since every Command shortcut starts by holding it. The text is written at the current cursor when it is ready; with no text field it is still saved to History. The record button at the top of the panel and Start Recording in the menu bar menu do the same. Esc cancels and deletes the recording.
4. Microphone: "Audio and shortcut" in Settings lists the input devices that are connected. The one you click is locked (by the device's persistent ID, not its name) and is the only one out records from. When the locked device is absent, out does not switch to the system default or the built-in microphone; it records nothing. The moment it disconnects (while not recording), the status capsule and the panel say so; if it disconnects during a recording, the recording stops and what was recorded stays in History; after that, Fn only shows the notice. If the system's input switches from the locked device to another one during a recording, that recording stops too, and what was recorded stays in History. The record row turns orange, and a click on its record button opens Settings, so you can reconnect the device or click another one to lock it instead. "System default" removes the lock and follows the system's current input device.
5. Settings → "Audio and shortcut" shows whether Fn has been taken over. With Fn selected and the key monitor running, out temporarily sets the system's "Press 🌐 key to" action to "Do Nothing", so Fn does not switch input sources, open the emoji picker or start the system's dictation on a double press. If a permission is missing, click "Allow and take over Fn"; the system action is never disabled while the monitor is not running. Do not let another voice tool listen to Fn at the same time. To use another shortcut, click the shortcut key at the left of the panel's record row and press the new one: Fn, a Command key on its own, an F-key, or a key with Control or Option. Esc or a second click keeps the current one. Shift, Control or Option on its own, Esc and Control + Option + V cannot be the shortcut.

A click on Out! in the menu bar opens its menu, where every item has a sign before its name, and shows the panel along with it, also when the panel has been hidden, closed or minimized; the app in front keeps the keyboard, so Start Recording in the menu still writes there. The panel is a narrow vertical glass window, 280 pt wide, that shows the desktop behind it with no opaque background, light or dark with the system appearance. Its width is fixed and its height follows the content: when a block opens, the panel grows to show it in full (up to the screen's height); when Multiple Macs is collapsed or the Shelf is cleared, it gets shorter. You can also drag the top or bottom edge to make it shorter, and the content then scrolls inside; that only lasts until the next block opens, when the panel grows to fit again. Its position is remembered. From top to bottom: the title row (four buttons at the right end: one that shrinks the panel into the bar kept on top, Type the Clipboard, History and Settings); the record row (the shortcut, which you can click to change, and the record button); Multiple Macs, showing whether each Mac is online (Manage opens it, and the arrow to the left of its title collapses the block to its title line); and the Shelf at the bottom. While a permission, a key or the shortcut is missing, a setup card appears on the panel. The panel is the whole app: there is no separate settings window and no pop-up dialog.

History and Settings share a drawer beside the panel. The History button or the gear (or ⌘,, or "Settings…" in the menu bar menu) slides the window out sideways by 316 pt to show the full History (search, clear, and per record: expand, retry, copy, delete) or Settings (recognition and polishing, each service's API key, audio and shortcut, the personal dictionary, general). Switching between History and Settings crossfades inside the drawer; the same button again, or the × at the drawer's top right, slides it back. Every piece of text in the panel and the drawer (results, history records, notices, this Mac's name, Tailscale addresses, pairing codes, dictionary words) is copied with a click on the text itself. The drawer opens to the right, or to the left when there is room only on that side; either way the panel's column stays where it is on screen. The drawer is as tall as the panel and scrolls inside.

The title row is one piece of glass with the rest of the window: it has no cover of its own, and content starts a little below it and, scrolled, ends at its lower edge, in the panel and in History and Settings beside it (until 0.1.82, on macOS 26, content passed under the row with the system's soft blur, which showed as a band apart from the window over some backgrounds). No list in out shows a scroll bar; each scrolls with the wheel or the trackpad. While recording and processing, a small capsule shows the status: next to the text cursor, right under its line, when the field in front reports where the cursor is, and otherwise just below the menu bar at the top of the screen. It is the same glass as the panel, light or dark with the system, with the state as a tint: while you speak it turns green and pulses with the volume so it is easy to spot in peripheral vision, and when done it is green, amber when the text did not reach its field, and red on an error; next to the text cursor it goes where the cursor goes, and below the menu bar it moves along the top edge only when the input focus or out's own panel is directly under it. Once dragged somewhere (it, or the bar kept on top, see [Kept on top](#kept-on-top)), it shows there whenever the text cursor's place is not known, and for as long as it stays shown it no longer moves by itself. Most of the panel does not animate, to avoid frame-by-frame window resize stutter: opening, closing and showing a result happen in one step, content and window alike. The exceptions are details opened manually, which open and close smoothly: a Mac's address, permissions and test in Multiple Macs; and Manage. Only the content animates; the window matches the content's current height on every frame (rounded to the pixel) with no animation of its own, so the two stay in sync. The panel's position is saved, and the capsule moves, only after the transition settles. Other animations are small and lightweight: the highlight of segmented choices, the drawer sliding out beside the panel, a ring spreading from the record button while recording, buttons shrinking slightly when pressed, and the capsule fading in and out. With Reduce Motion enabled, these transition immediately as well. The menu bar menu starts, stops or cancels a recording, types the clipboard, opens Settings, copies the last result and quits the app. Closing the panel does not quit the app. The panel is an ordinary window on the desktop (Space) where it was opened and stays there: a click on Out! on another desktop or in a full-screen app switches to the panel's desktop instead of moving the panel (only when the system is set not to switch desktops when switching apps, and the panel therefore cannot appear, is it brought to the current desktop). When the app launches again at login or manually, the panel reopens only if it was open when the app last quit; on the first launch of a new version it always appears. Either way it does not take keyboard focus. Opening out again from Applications also shows the panel.

Quitting out, revoking Accessibility or switching to another shortcut restores the original Fn action; an action you chose in System Settings in the meantime is not overwritten. After a crash, the next launch restores the saved original action; until then, it can be changed back in the system's keyboard settings. Fn + arrow keys, Fn + Delete and Fn + F-keys continue to work as key combinations and do not start a recording; the F1–F12 setting is not changed.

To update the system's Fn setting at once, out calls HIToolbox's private `TISGetFnUsageType` / `TISUpdateFnUsageType` at run time; no system file is modified. This is not allowed in the Mac App Store, and a future macOS may remove it. When it is unavailable the panel says so, and "Do Nothing" has to be chosen by hand in the keyboard settings; out does not claim to have taken over Fn.

## Kept on top

The status capsule and the bar kept on top are one window: the two never show at once, and they share one place.

Not kept on top, the window is the capsule: it shows only while you record, while out works and with the result. With the pointer over it, a pin button appears in it; click it to keep the window on top right where it is.

Kept on top (with that pin, with Keep on Top in the menu bar menu, or with the first button in the panel's title row, which shrinks the panel into it), the window stays as a glass bar above every window, on every desktop (Space) and over full-screen apps, and never takes keyboard focus from the app in front. Its first row is the capsule: while you record, while out works and with the result, what the capsule would show shows there, in place, and no capsule appears. Otherwise the row has the record button, whether this Mac is ready, its shortcut, and the last result, which a click copies. At the end of the row are three buttons: hide or show the Shelf, stop keeping on top (the window goes back to being the capsule), and back to the full panel. Under the row is the Shelf as a strip: drop files, images or text on the bar to keep them there, click an item to copy it, drag it out to use it, and + puts what is on the clipboard there.

Drag the bar, or the capsule, by any part that is not a control. Where you leave either is the place of both, kept across restarts (the capsule still goes next to the text cursor when the field in front reports where it is); until you first drag one, the capsule finds its own spot below the menu bar and the bar starts at the top center of the screen. Opening the full panel from the bar stops keeping on top, and unchecking Keep on Top in the menu bar menu stops it and leaves the panel as it is; a click on Out! in the menu bar only brings the bar to the front. After a restart the bar comes back if the window was kept on top.

So that the bar does not hide what is under it, it moves aside when the pointer leaves it, by half its height and away from the side the pointer left by: leave it upward and it moves down, downward and it moves up, to the right and it moves left, to the left and it moves right. It stays on its screen (against an edge it does not move that way), does not move while a mouse button is held, and goes back to its place once the pointer has been away from it for a moment. Dragging it while it stands aside makes where you leave it its place.

## Shelf: a clipboard shared by several Macs

The Shelf is at the bottom of the panel. Drop files, images or text anywhere on the panel and they stay there; Paste puts what is on the system clipboard there.

- Use: click an image or a file to copy its link (see Links); click text to copy the text. Drag an item straight into another app or the Finder. With the pointer over an item, its picture floats out beside it, larger; the × at its top right removes it. The right-click menu has Copy link; Show in Finder when the item is on this Mac, or Download to This Mac when it is not, which fetches it and shows it in the Finder when it has arrived; Copy the file, which puts the file itself on the system clipboard (an image both as a file and as pixels); and Remove.
- Links: where one of your machines is the primary helper on the Monitor page, an image or a file is sent to it as it is put on the Shelf, and Copy link, first in the right-click menu on any of your Macs, puts its link on the clipboard; text gets a link the same way. A click on an item always copies the item itself (on a Mac that does not have it yet, it is downloaded first). The primary helper keeps the item, and the link is `http://<the primary helper's tailnet name>:8126/s/<a random token>/<the file's name>`. The link opens on any device on your tailnet, in a browser or with `curl`, whether or not this Mac is on. Anyone on the tailnet who has the link can open it, and nothing outside the tailnet can reach it. Pictures, video, sound, PDF and plain text open in the browser; any other file is downloaded. Copying the link of an item that has one sends nothing again. A file that is not on this Mac has its link from the primary helper once the Mac it was put on has sent it there; until then it has to be fetched first. On the Mac that made a link the item carries a small link mark in its top left corner; Remove link in the right-click menu takes the link down, and so does removing the item from the Shelf, once that Mac sees the removal. The primary helper keeps up to 10 GB of linked files and refuses more rather than letting one go. It has to be on a tailnet, and gives links only where it can tell that its address there is Tailscale's: on Linux by the network interface, on other systems by the name MagicDNS gives the machine. This Mac does not have to be on the tailnet. Links need helper 2026.11.22.1 or later on this Mac and on the primary helper, and the primary helper learns of this Mac within ten minutes of both running.
- Sharing: the Shelf follows Multiple Macs, your other Macs on the Monitor page; there is nothing else to set up. Each Mac keeps one connection to each of the others, and additions or removals on one apply to all of them; two Macs that cannot reach each other but both reach the same third Mac stay in step through it. The title shows how many Macs it is shared with. With Multiple Macs off, the Shelf is local.
- Offline: a Mac that is offline keeps using its Shelf and catches up when it is back; an item removed elsewhere meanwhile is not brought back by it.
- Images and files, whatever their size, are not sent to the other Macs when added: the Mac they were put on keeps them, the primary helper keeps the copy their link opens, and the other Macs get a card of a few dozen KB with the name, size, origin, a thumbnail (an image, a frame of a video, a page of a PDF) and a down arrow. A click on the card fetches the file from a Mac that has it, with the progress on the card, and copies it once it is here; where no Mac that has it is online, it comes from the primary helper. Download to This Mac in the right-click menu (or starting to drag the card) fetches it too; a click on the card while it is coming stops it. A drag waits for the fetch to finish. Text is sent to every Mac whole. What a version before 0.1.59 put on the Shelf keeps the old rule: sent whole up to 8 MB, a card above.
- Thirty days: every item leaves the Shelf thirty days after it was put there, on every Mac, card and bytes alike, and its link is taken down with it. The tooltip of an item says the day. Each Mac checks once a minute, so a Mac that was away when the day came clears it when it is back, and none takes in an item older than that.
- Where a file is fetched from: any online Mac that has it, including one that fetched it before. When two Macs cannot reach each other but both reach the same Mac, that Mac fetches it first and passes it on (one hop at most). When no Mac with the file is online, the card shows an offline icon; it can be fetched once one is back.
- Resume: when a transfer stops (network loss, a stop, quitting out), the part already received is kept, and the next click continues from there.
- Space: the Mac that added a file keeps an APFS clone of it, which takes no extra space on the same volume; moving or deleting the original later does not affect the Shelf. When the copies fetched on another Mac exceed 5 GB, the least recently used are released (the card stays and can be fetched again); "Release local copy" in the right-click menu does it by hand. The adding Mac's own copy is never released automatically.
- Transport: small items travel as text inside messages; large files as raw chunks over the same connection, taking turns with cards, removals and other messages, so other items keep syncing during a large transfer. The speed depends on the route between the two Macs; through a Tailscale relay it is slower than direct.
- Limits: 40 items, the oldest giving way; no limit on file size; images and text from the clipboard up to 64 MB; folders are not supported yet (compress one into a file first).
- Storage and transfer: files are kept in `~/Library/Application Support/Qingyan/Shelf` (folder mode 0700), unencrypted on disk, not uploaded to any cloud or model service. They travel only between your Macs, through the helpers and on the same encrypted connection as text. An item given a link also goes to your primary helper, through the helpers' tunnel, and is kept in that helper's configuration folder (`hosted`, readable by its user only), unencrypted, until the link is removed.
- Diagnostics: create `shelf-probe.trigger` in `~/Library/Application Support/Qingyan/`; out reads and deletes it within two seconds. `big 20` adds a generated 20 MB file, removed after two minutes; `fetch` fetches every large file not on this Mac; any other text adds an item "out sync self-test", removed after 8 seconds. This lets you check another Mac's Shelf from a terminal.

## Type the Clipboard

Some places refuse a paste: password fields, forms that block it, and remote desktops or consoles that do not share a clipboard with this Mac. Control + Option + V (or Type the Clipboard in the menu bar menu, or the keyboard button in the panel's title row) types the clipboard text into the active field instead, key by key, as if typed by hand. It uses the Accessibility permission out already has.

- The keys wait until Control, Option and V are released, then go out at about 80 per second, with a short pause after each line. Esc or the capsule's Cancel button stops typing; so do another window coming to the front, a click or a key press, and a change of input source. The capsule shows how far it has gotten.
- Line breaks are typed as Return and tabs as Tab, so a multi-line script typed into a console runs line by line. It also types into password fields. Both apply to this action only: dictation still never sends Return and does not write into password fields.
- When typing into an app on this Mac, characters are typed with the keys of the current layout, and other characters (such as Chinese or emoji) as Unicode text. In a remote desktop (Screen Sharing, Jump Desktop, Windows App, VNC viewers, TeamViewer, AnyDesk, Parsec and the like), US keys are used because the other end reads keys, nearly always with a US layout; text containing characters that no key can type is not typed there at all, so nothing arrives with missing characters. When an input method such as Pinyin is active, an ASCII-capable layout is used for typing and the input method is restored afterward.
- At most 20,000 characters. Nothing typed is kept: not in History, not on the panel.
- This feature originated from PasteForce, a separate app that did only this; out works with any layout and types any character, waits for the shortcut keys to be released, and paces the keys for remote desktops.

## Editing existing text by voice

With Text polishing turned on in Settings and the Polish style, you can speak an editing command without selecting anything: put the cursor in a text field and say, for example, "clear everything", "delete the previous sentence and replace it with Thursday at three", "change Wednesday to Thursday" or "no, let me start over…".

- It takes two steps. The first is the same request as the usual polishing, with one more question: could this be an editing command? Only the transcript is sent in this step. If the model says no, the text is written as usual, exactly as before.
- Only when it could be a command is there a second step: out reads the text in the current field (split at the cursor into the part before and the part after) and sends it with what you said to the text model. The model either decides it is ordinary content after all (you may be dictating an instruction for a colleague or an AI assistant) and it is written as usual, or returns the complete new content of the field.
- Only the part that changed is written back: out compares the old and new text, drops the common beginning and end, selects the different middle through Accessibility and pastes over it. Unchanged text is not touched; clearing selects everything and deletes it. The field is read again just before writing, and if it changed since it was sent to the model, nothing is changed.
- When the field cannot be read (terminals, password fields, custom-drawn fields that expose no Accessibility text, documents over 6000 characters), out falls back to editing only the previous dictation: the text the last dictation wrote, within 10 minutes and with focus in the same window. If no key was typed and no click made since that text was written, it deletes the same number of characters backwards and pastes (this also works in a terminal); otherwise it deletes nothing. With no previous dictation either, what you said is written as ordinary content, and the capsule says the field could not be read.
- Each Mac's status in Multiple Macs: it counts as connected when this Mac can reach it, or when it called in and holds its connection (the long-lived connection that shares the Shelf). When it can reach this Mac but this Mac cannot reach it, the status reads "One-way connection" in orange, with a line saying what works and what does not, rather than "Online". A Mac behind a router that allows only outgoing connections (its own Tailscale off, reaching the tailnet through the router) cannot be reached by the others but can reach them: its text is written on the other side as usual, the Shelf syncs both ways and the other side shows it online; only writing text from the other side to it does not work.
- When text goes to another Mac, that Mac reads its field and sends the content back to the Mac you speak to, and it is that Mac that applies the edit; only a sender that has completed the handshake (the knock session) can read it.
- Privacy: the field's text is sent to the polishing service only when what you said could be an editing command; ordinary dictation neither reads nor uploads it. With Text polishing off or a style other than Polish there are no such steps and no editing by voice.
- The two kinds of misjudgment: a command taken as content is written into the field (delete it and say it again); content taken as a command changes the field (undo with ⌘Z in that app). When unsure, the second step leans towards ordinary content.
- History records what you said, not the edited text.

## Multiple Macs: speak on one, and the text appears on the Mac you are controlling remotely

On each Mac, install out, and install the Monitor helper from the Monitor page with direct connections on. Under Multiple Macs on the panel, turn on Work across Macs. There is nothing to pair: out works with the Macs on your Monitor page.

1. While the Monitor page is open in a browser your Macs trust, it tells each Mac's helper about your other Macs with out: their names, their tunnel addresses and the keys they connect from. It sends this over each Mac's own tunnel, signed with the key the Mac trusts, and only to Macs that verify the signature.
2. out on each Mac asks its helper for that list, and the Macs appear under Multiple Macs. A Mac without the helper, or with an older version, takes no part, and the panel says so. Its button opens the Monitor page's Install window with "Also install out" switched on. The install line there installs the helper for your account with what out needs — direct connections and remote updates (through which the page reaches the Mac) — and then installs out.
3. From then on press Fn on either Mac as usual. Where the text goes is not chosen by hand: a knock decides (see below).

**How the Macs reach each other**

- out connects to its own helper through a socket in the helper's configuration folder that only your user account can open; out itself listens on no network port. The helpers carry out's connections: where both Macs are on the same Tailscale network, through it first (from helper 2026.11.22.3; each helper proves the same key to the other as on the tunnel; from 2026.11.22.8 also from a Mac that is not on that network itself but whose router is); otherwise, and when that does not answer within two seconds, through their tunnel: directly between the two Macs where a path forms, through a public DERP relay where none does. Encrypted end to end either way. Two Macs on different networks, or one behind a router, reach each other without Tailscale.
- A helper lets another Mac's helper open out's connection and nothing else, and only if that Mac is on the list the Monitor page signed. A Mac forgotten on the Monitor page is taken off the others' lists, and its open connections end.
- Inside the tunnel, out still encrypts each connection itself: each side shows a key it keeps in the login keychain and a one-time key, and the session key comes from three key agreements. Every frame after the handshake is encrypted and numbered; a frame that is altered, replayed, lost or reordered ends the connection.
- Shelf items over 8 MB still sync as cards and are fetched when opened; through a DERP relay that takes longer than over a direct path.

**The knock**

- When a recording stops with a remote desktop in front (Screen Sharing, Jump Desktop, or another remote-desktop app out knows, such as Windows App, VNC viewers, TeamViewer, AnyDesk, Parsec or Screens), the Mac you spoke to connects to your other Macs and types a knock into that window. In front of any other window it asks no other Mac, and the text is written on this Mac at once. The knock uses only right-hand modifier keys (holding Option, six presses of Shift or Control) and produces no characters; the combination of six is chosen at random for each recording.
- The remote desktop forwards the knock like any other keys to the Mac you are controlling. out on that Mac recognizes the knock in its key monitor and answers "it's me". The text goes only to it and is pasted at its cursor; both Macs keep a copy in History. The others only saw a handshake and get no text.
- The Mac the window's title names is asked first. A remote desktop's title usually shows the computer's name, which out compares with each Mac's name on your Monitor page and with the name that out on that Mac gave before. Only when that Mac does not claim the knock, or the title names none of them, are the others connected and knocked at; Macs that could not be reached the last time come last.
- When no Mac answers in a remote-desktop app other than Screen Sharing or Jump Desktop, the text is written into that window as usual.
- All this happens while the recording is being transcribed. If keyboard focus is still in the same window when the text is ready, the answer is used as is; if you moved to another remote window meanwhile, the knock is typed again; if you moved to a window on this Mac, the text is written there without asking any other Mac.
- While the text is on its way, both capsules say so. On the Mac you are controlling, a capsule says which Mac the text is coming from as soon as that Mac recognizes the knock, and stays until the text is written; if the Mac you spoke to cancels, recognizes nothing or loses the connection, it goes away. On the Mac you spoke to, the capsule says which Mac it is sending the text to.
- Several remote windows at once are fine: the knock reaches only the one with keyboard focus.
- When the current window is Screen Sharing or Jump Desktop but no Mac answers (out not running there, the Mac not on your Monitor page, or the remote tool did not forward these keys), the text is not pasted into the remote window; it stays in History with the reason.
- A Mac that cannot be reached holds things up only when the search comes to it: its helper is given 3 seconds to reach it, and the handshake 1.5 seconds more at most.
- Known limit: the knock reaches the remote desktop app on the Mac you spoke to and, through it, the app in front on the Mac you are controlling. The keys are modifiers pressed while Option is held, not double presses of any single key, so they rarely trigger shortcuts; an app that binds such a combination to an action will run it.
- Diagnostics: create `knock-locate.trigger` in `~/Library/Application Support/Qingyan/` (it may contain the interval between key presses in milliseconds); within two seconds out knocks on the current window without sending text and appends the result (handshake time, who answered, how long it waited) to `knock-locate.log` in the same folder.

- When sending fails (out not running there, a helper not running, no network), the text is not pasted on this Mac instead; it stays in History on the Mac you spoke to, and the capsule says why. Connecting and answering wait 8 seconds at most.
- Whenever the text does not go into a text field on the other Mac, the capsule turns amber at once and says which Mac, why (no text field found, a password field or secure input, no Accessibility permission, not allowed, could not be reached) and where the text is: on that Mac's clipboard, or on this Mac's clipboard (⌘V). When the other Mac pasted without finding a text field and no app took the text, or did not respond after the text was sent, the text may still have gone in, so the capsule says it is not confirmed rather than not typed.
- Apps built on Electron, such as Visual Studio Code, Cursor and Slack, show their text fields to other apps only when asked. When a recording starts, or a knock arrives, with one of them in front, out asks once; the app takes about two seconds to show them, and before writing out waits for that, so their text field is found like any other. Only the first text into a newly opened one can take up to two seconds longer. In Visual Studio Code and Cursor, being asked can turn on screen reader optimized mode unless `editor.accessibilitySupport` is set to `off`.
- Some apps show other apps no text field at all, such as the ChatGPT app and pages in Chrome. When no text field is found, out still presses ⌘V, with the text on the clipboard only for the app that asks for it, marked as transient so that clipboard history tools leave it alone, and for this Mac only. When the app takes it, the text went in, and the capsule says so as for any text field; when no app takes it within a second, the text stays on the clipboard and the capsule says it is not confirmed. A clipboard tool that ignores the transient mark and reads the clipboard at that very moment would make a paste that did not go in look confirmed.
- When the receiving Mac has nowhere to write (a password field, Secure Keyboard Entry, no Accessibility permission), the text is still saved to its History, and the reason is reported to the Mac you spoke to.
- Only your other Macs listed by the helper can reach out on a Mac; nothing else can connect to it.
- Recordings transcribed later, after the network returns, go only to History and are not sent to another Mac, as they are not written to this Mac's field either.
- When the receiving Mac is recording itself, received text is still pasted and saved to History without interrupting its own capsule.

## The screen on the Monitor page

Your Monitor page can show this Mac's screen, where it can be controlled as well as viewed, as it shows any machine's: from this Mac's terminal there.

- What shows it: this Mac's own Screen Sharing (System Settings → General → Sharing → Screen Sharing), as any VNC viewer sees it. The page's viewer signs in to it with an account on this Mac, typed on the page and kept there only. The Monitor helper on this Mac carries the bytes between the page and Screen Sharing, which it reaches on this Mac's own loopback address, and reads none of them. out takes no part in it and records nothing.
- What is sent: the picture as Screen Sharing sends it to a VNC viewer, at the quality and compression chosen in the page's settings, with no sound. What comes back: the pointer, keys, scrolling, and clipboard text sent from the page's clipboard panel.
- Who may open it: whoever may open a terminal on this Mac from the page. The page starts a session with a command signed by a key the helper has pinned, and the helper's console switch decides, as for the terminal. A Mac's screen is shown only where out is installed on it.
- macOS shows its own Screen Sharing indicator while a page's session is open.
- Screen Sharing decides what a viewer may do. A user it lets observe only (for example under Remote Management with Observe but not Control) sees the screen, but clicks and keys do not reach the Mac.
- Until 2026-11-24 the page could also show this Mac's screen in High Performance mode, and until out 0.1.91 the panel had a "Show this screen on Monitor" switch for the page. Both are gone. With a Monitor helper older than 2026.11.25.2 here, the page's screen still waits for that switch: the helper updates itself. Another Mac's out still shows this screen in High Performance mode (below).

## Another Mac's screen in out

Each Mac in Multiple Macs that is reached through the Monitor helper has a screen button after its name. It opens that Mac's screen in a window of this out, where it can be worked as well as viewed: the session the Monitor page gets, without a browser. The picture, the pointer's shape, the clipboard and that Mac's sound come over; the pointer, the keys by their place on the keyboard and the wheel go back.

- No switch is needed on the other Mac: any Mac of yours in Multiple Macs that may type text on it can open its screen. The other Mac needs out of the same version or newer (from the version that moved the client here; an older out on that Mac is told to update), out running, and Screen Sharing on. The window opens only once that Mac's picture has come; until then that Mac's row in Multiple Macs says Connecting to the remote window… in place of Online, with no spinner, and if the screen cannot be opened (no picture within 30 seconds included), a message says why and no window is left open.
- One kind of session: Screen Sharing's High Performance mode, with Dynamic Resolution. HEVC (H.265) video of a display of the session's own that follows the window, at up to 60 Mbps, with that Mac's sound; that Mac's own displays are dark meanwhile. The video is 4:4:4, one stream for the whole picture, decoded by this Mac's hardware, and never H.264. It needs Apple silicon on that Mac, where Screen Sharing makes a display for a session and sends HEVC, and HEVC decoding in this Mac's hardware: a Mac without Apple silicon (an Intel Mac) is not shown in out: it has no screen button once its out has told this Mac what it is (as it answers the online check, from the version after 0.1.94, or when its screen was asked for), and before that a message says so; the Monitor page still shows it. Until out 0.1.94 there was also a standard kind, without sound, which sent that Mac's display as it is in Screen Sharing's own Adaptive Quality codec, and a High Performance button that chose between the two.
- Signing in: the first time, a dialog asks for an account on that Mac (the name of the user signed in there is filled in), before any window opens. With "Remember in this Mac's keychain" on, it is kept in this Mac's keychain for that Mac, once a session has opened with it, and asked for again only if that Mac no longer accepts it. The password goes to that Mac encrypted end to end and is not kept there.
- The pointer: that Mac sends its pointer as a picture at one pixel a point, which is soft on a display of two pixels a point. When the picture is one of the standard pointers (the arrow, the I-beam, the hands, the crosshair, the resize arrows of a column, a row and a window's edges), this Mac's own pointer of that kind is shown in its place, sharp, at this Mac's pointer size. Any other pointer (an app's own, one with a badge, one in a custom color) is shown as it was sent.
- Who the client is: this out. It is a Screen Sharing client of its own, the one the Monitor helper on that Mac ran until 2026-11-25, moved here. It signs in to that Mac's Screen Sharing, reads its picture, sound, pointer and clipboard, and sends the pointer, keys and clipboard, just as the system's Screen Sharing window does. The helpers on both Macs only carry bytes: neither reads, signs in or makes anything of the session.
- How it travels: this out proves which Mac it is to the other Mac's out, with the same handshake as for sending text, and asks for the screen; out on that Mac then connects to its own Screen Sharing and carries its bytes both ways on that connection without reading them: the TCP connection, and its two UDP ports as datagrams, sent from one of that Mac's own addresses as Screen Sharing expects (where one address does not get the media through, the next is tried). That connection goes only through the two Macs' helpers and their tunnel. A Mac reached at a plain address, not through the helper, is not offered.
- While the screen is shown and the window works that Mac, the picture fills the window: there is no title row, no line at the bottom and no close, minimize or zoom button of the window's own, only three round buttons of frosted glass at its right side, Close, Full Screen and More, with the picture under them blurred; on or off, a button is frosted glass, light with a black sign or dark with a white one. Over the picture the strip and the line are solid, in the window's own color, with no blur and no fade into the picture; while no picture is shown they are on the window's own glass. With the pointer on More, or a click on it, the other buttons come under them (in another column to their left where the window is too short for one), the title strip comes over the top of the picture with the Mac's name and the close, minimize and zoom buttons, and the connection line comes over its bottom; they stay while the pointer is on them or Info is open, and go a moment after the pointer is back on the picture. A button's name is shown at its left while the pointer is on it. All the buttons look the same, and one that cannot be used at the moment is not shown, not grayed. It is the same in full screen. Until the picture is double-clicked, while a drag still moves the window, they all stay: the title strip with the Mac's name, the connection line and every button, and large words at the picture's top left say Double-click to control. While the window connects again, asks for an account again or says why the screen is not shown, they stay too. The window is moved by its title strip. Where the picture's proportions leave room around it, the window is glass, like out's panel; in full screen that room is black.
- In a window, the pointer and the keys go to that Mac only after a double-click on the picture: until then a press on the picture moves the window, the pointer over it stays this Mac's arrow, and the line at the bottom says the window observes. The window stops working that Mac when it is no longer in front, and a double-click starts it again. In full screen the pointer and the keys always go to that Mac. There is no Disconnect button: closing the window, with Close or the title strip's button, ends the session, and a window that is not connected offers Connect Again.
- The clipboard is always shared: while the window is in front and works that Mac, text copied here goes to that Mac's clipboard, and text copied there comes here.
- The buttons, in two looks that follow the system's appearance: in the light appearance a button is white with a black sign and, while on, black with a white sign; in the dark appearance and in full screen it is the other way round:
  - Close, which closes the window and ends the session; Full Screen; and More, which brings the others. These three are always there.
  - Scaling, kept for each Mac: on, the picture fits the window and the window keeps that display's proportions; off, it is shown at its own size, a point of that display a point here, and the window scrolls when the pointer reaches an edge (the window has no scroll bars).
  - There is no High Performance, Dynamic Resolution or Full Quality button: every session is High Performance with a display of its own, at the most Screen Sharing may send. The display is asked for in points, at this Mac's pixel scale; whether that Mac makes it a Retina display is macOS's choice there, and the window follows the size that Mac reports, so the pointer lands where it is drawn (a helper there before 2026.11.22.5 asked for one twice the window's size on a Retina Mac, and the pointer drifted from the picture). A new size can take macOS several seconds on an older Mac. When the window takes a new size, the picture stays blurred while that Mac changes the display, as in Screen Sharing's own window, and clears once the new picture arrives, or after eight seconds; with Reduce Motion on, it clears without animating. The display follows the window however it takes a new size: dragged, zoomed, tiled by macOS, or in and out of full screen (before 0.1.64, only when dragged and in and out of full screen). With a helper there from 2026.11.22.7, a Mac that does not make the size asked for at this Mac's pixel scale makes it at a pixel a point instead, and the pointer lands where it is drawn at either.
  - Sound, kept for each Mac: that Mac's sound plays here; off, it is not decoded.
  - Keys, only while the window works that Mac: a menu that sends keys this Mac's system keeps for itself: ⌘Tab, ⌘Space, Mission Control (⌃↑), App Windows (⌃↓), Force Quit (⌥⌘Esc) and Lock Screen (⌃⌘Q).
  - Info: everything known of the connection and the stream.
  - In the title strip, the Mac's name alone, in the middle of the window, with no dot beside it; with the pointer on it, whether its screen is shown, connecting or not connected.
- At the bottom, with the title strip, a line with the road the session took (tailnet, the two Macs' own Tailscale network, or tailcat, the helpers' tunnel), the path on it with the latest round trip (Direct and the endpoint, Peer relay and the relay, or DERP and the region, from a ping a second as `tailscale ping --until-direct=false` sends; or Through the router, where this Mac is not on the tailnet itself and its router carries it there, with the time a connection to that Mac's helper takes, from helper 2026.11.22.8), the display's size, the codec, frames and bits a second, and whether the window controls or observes. Its dot is green for a direct path, yellow for a peer relay, orange for DERP and red when the last ping got no answer. A click on it, or Info, shows everything: both roads' paths, with the fastest, mean and slowest round trip and the share lost over the last minute and a graph; the last ten pings of each as `tailscale ping` prints them; and the stream as the other Mac's helper counts it (frame rate, bit rate, sound packets, pictures lost, key frames sent and asked for, packets that failed to authenticate, pictures skipped because this Mac fell behind) next to what this Mac receives. The pings need this Mac's helper 2026.11.22.4 or later, the stream's numbers the other Mac's; with an older helper the line says so or leaves them out.
- Not in the window yet: choosing one of several displays, HDR, two displays at once, and dragging files between the Macs.
- Command shortcuts such as ⌘Q and ⌘W go to that Mac, not to out here (system shortcuts such as ⌘Tab stay on this Mac; the Keys menu sends them); close the window with its close button. Keys and buttons held when the window goes to the back are let go there.
- Speaking into it: with the window in front, a dictation goes to that Mac, as it does behind a remote desktop, but without the knock, since out knows which Mac the window shows. Fn stays this Mac's.
- One viewer at a time: while the Monitor page or another Mac views a screen, the window says so. On the Mac being viewed, the panel says which Mac is viewing and has a Stop button, and so does the menu bar menu.

## Releases and updates

- Builds: every push to `main` is checked (`swift run QingyanChecks`) and built by GitHub Actions (`.github/workflows/release.yml`). A build is published when the maintainers tag it `v0.1.<build>`: the workflow signs it and makes one release for that version, the only one that holds it, containing `out-0.1.<build>.zip` (the app, which `install.sh` and installed copies download) and `out.json` naming it. There is no disk image or other installer. The build number only increases. 0.1.50 also carried the app as `put-0.1.50.zip` with a `put.json`, for copies installed while it was called put, which moved themselves to `out.app`; now that every Mac runs out, that pair is gone from it, later releases do not carry it, and the old pre-release `builds` that copies up to 0.1.48 read is deleted.
- Signing: a self-signed certificate, "input signing (SUB&SUB)", valid to 2036. Its private key is the repository secret `INPUT_SIGNING_P12` (with `INPUT_SIGNING_P12_PASSWORD`); a run without it (a fork) builds to check the code and publishes nothing. The certificate is not issued by Apple and does not pass Gatekeeper, so these builds are for Macs that already run out; public distribution would need a Developer ID certificate and notarization. Every build must be signed with the same certificate: macOS ties the app's permissions (Accessibility, Microphone, Keychain) to the signing identity, and a different certificate would make every Mac grant them again.
- Provenance: every published zip and manifest has a build provenance attestation signed by GitHub, which names the workflow run and the commit it was built from. To check a downloaded file: `gh attestation verify out-0.1.<build>.zip --repo subnsub-tools/subnsub-out`. It proves where the file was built, not that the code is safe; that is what the source here is for.
- Where updates come from: first this repository's releases (`https://github.com/subnsub-tools/subnsub-out/releases/latest/download/out.json`, the newest release's manifest, names the current build: version, file name, size, SHA-256; the package is `out-<version>.zip` in that version's own release, `v<version>`), then our site, which serves the same builds (`https://dashboard.subnsub.com/api/input/out.json` and `out-<version>.zip`), for a Mac that cannot reach GitHub. The site is asked only when GitHub gives no answer at all (no connection, or a server error or rate limit on its side): at once for "Check for updates", and for the automatic check once GitHub has been out of reach for 6 hours. An answer from GitHub, whatever it says, is never a reason to ask the site, so a build changed on the site alone is not installed by a Mac that can reach GitHub. GitHub's redirects are followed only to its own download hosts. Neither place needs a sign-in or token; the package always comes from the place whose manifest named it.
- Updating: an out installed in Applications reads `out.json` every 6 hours (and within a minute of launch). When it names a larger build number, out downloads and unpacks it and checks that the size and SHA-256 match `out.json`, that the version inside matches, and that **the signing identity is the same as the running app's** (the new bundle must satisfy the running app's own designated requirement). When everything passes, and no recording or delayed transcription is in progress, it replaces itself in Applications (`/Applications/out.app`) and relaunches. On the first launch of a new version the panel always appears in front of other windows (whether it was open before or not, and also after a manual install) without taking keyboard focus; an ordinary relaunch of the same version restores it only if it was open when the app stopped. Settings → General → "Install updates automatically" turns this off, and "Check for updates" next to it checks by hand. The feed being public does not weaken this: a replaced file fails the signature check and installs nowhere, and `out.json` only names a version, not where to download from.
- Keychain (since 0.1.8): API keys and this Mac's identity key are kept in the login keychain but stored and read through the system's `/usr/bin/security` tool (service `local.hopo.qingyan.vault`), not by the app itself. The keychain grants access by the program that stored an item and tells programs apart by Apple's Team ID; a self-signed certificate has none, so the keychain would recognize only each build's own hash and ask for the login password after every update. Items stored through `security` belong to that system tool, so updates no longer prompt. The cost: other programs running as your user can read them through the same tool without a prompt (about the strength of most command-line tools that store tokens); the content is still encrypted with the login password in the keychain, not a plain file.

## Models and data

- Services: recognition and polishing each use a service of their own, which may differ. Built in are OpenAI, Alibaba Cloud Model Studio, This Mac (on macOS 26 and later), Groq, SiliconFlow, and Custom: any service with an OpenAI-compatible API (enter its endpoint URL, such as `https://example.com/v1`; `http://` is accepted only for IP addresses, this Mac and local host names, for models on your own network). Each service has one key; a custom one may have none, and This Mac needs none. Models are picked from the service's suggestions, or "Other model…" takes a name; Verify asks the service for its model list and checks the key and the chosen model.
- Groq, SiliconFlow and Custom use the common OpenAI-compatible API: after you finish speaking, the whole recording is uploaded as WAV to `/audio/transcriptions` (120-second timeout), and polishing uses `/chat/completions` (60-second timeout, `max_tokens` 8192). These services show no text while you speak; the result appears once you finish. A recording must fit the service's maximum upload size (audio takes about 2.88 MB a minute; Groq accepts 25 MB, about 8.5 minutes, and SiliconFlow 50 MB). A larger recording is kept and can be retried from History after switching services. The personal dictionary is sent as a short prompt with the recording to Groq and custom services; SiliconFlow's API takes no prompt. A polishing result cut off by the length limit is refused and not written.
- Alibaba Cloud Model Studio: recognition streams while you speak over its realtime WebSocket (`qwen3-asr-flash-realtime`; out converts the 24 kHz recording to 16 kHz for it), so the words appear as they arrive; the personal dictionary is sent as context text, and its voice detection only splits the transcript at pauses — it never ends a recording (the shortcut still does). Polishing goes through `/chat/completions` with thinking turned off. The address defaults to the Singapore region (`dashscope-intl.aliyuncs.com`) and can be changed in Settings for another region or a workspace's own domain, since a key works only in the region it was created in. Verify opens the realtime socket to check the key and the speech model, rather than looking up the model name in a list.
- This Mac: on macOS 26 and later, the system's own speech model through SpeechAnalyzer recognizes the recording on the device — the audio never leaves this Mac, and the words appear as they arrive. Its "model" is the spoken language, one per recording (`zh-CN`, `zh-TW`, `yue-CN`, `en-US`, `ja-JP`, `ko-KR` are suggested, and any locale identifier can be typed). The model is downloaded from Apple and kept by macOS, which shares it with other apps: Settings shows its state for the chosen language and has Download, and a recording waits for it until it is installed. The personal dictionary goes along as contextual strings. There is no key and nothing to verify. Polishing still uses the chosen polishing service, so the recognized text leaves this Mac when Text polishing is on.
- The built-in services' addresses and suggested models are taken from their documentation as of 2026-11 (Model Studio: `qwen3-asr-flash-realtime`, `qwen3.8-flash`; Groq: `whisper-large-v3-turbo`, `openai/gpt-oss-120b`; SiliconFlow: `FunAudioLLM/SenseVoiceSmall`, `deepseek-ai/DeepSeek-V4-Flash`) and **have not been verified with real keys**; when a model is retired, enter the new name with "Other model…". Editing by voice depends on the model following the response format strictly; test another model before relying on it.
- The rest of this list is about OpenAI. The default is `gpt-live-transcribe`, 24 kHz mono PCM streamed over a WebSocket while you speak; pressing Fn commits explicitly, and server-side silence detection never ends a recording.
- `gpt-transcribe` is OpenAI's high-accuracy model for recorded speech: after you finish, the whole recording is uploaded as WAV to `/audio/transcriptions`, with the languages to expect (Chinese, English: `languages[]`) and the personal dictionary's words (`keywords[]`). If the API rejects these hints with a 400, the same recording is sent again without them, so the dictation is not lost. A recording may be up to 25 MB (about 8.5 minutes).
- `gpt-4o-mini-transcribe` is offered for compatibility (over the live connection; it may return text only at the end; OpenAI has announced its retirement on 2027-02-26). Model names come from OpenAI's current documentation; check what your own project can use.
- Text polishing is a switch in Settings → recognition and polishing, off by default, and nowhere else: the panel has nothing about polishing. Off enters the transcript as is, sends nothing to a polishing service, and hides every other polishing setting; settings saved by a version before this switch are read as off, whatever their earlier on/off said, so out polishes only after Text polishing is turned on in Settings. Turned on, it starts with the Polish style, and Style, Text before the cursor, the polishing service and model, Custom styles and the polishing service's key appear. Polish: after transcription, one `gpt-4.1-mini` Responses API call. It only adds punctuation and paragraphs, removes meaningless fillers (um, uh), stutters and what the speaker explicitly took back, and may fix obvious homophone errors; it does not summarize, shorten, rewrite, reorder, embellish or translate. This does not rely on the instructions alone: the result is compared with the raw transcript character by character (ignoring punctuation, white space and case, by longest common subsequence); if more than a fifth of the original characters are dropped (at least 12 allowed) or more than an eighth added (at least 6 allowed), the model's result is not used, the raw transcript is written, and the capsule notes that polishing changed the wording; sentences under 12 characters are not compared. Structured, Formal and custom styles each send one request that rewrites the wording — Structured turns what you said into a clear prompt for an AI assistant, Formal into formal written prose — their result is not compared with the transcript, and editing by voice is not available with them. Custom styles are written in Settings (at most 12, a name up to 40 characters and instructions up to 4000), and their instructions are sent with each dictation to the polishing service. A delayed transcription uses the style chosen when it was recorded (as is, without polishing, for a recording made by a version before this switch); a manual retry uses the one chosen now. Translate and Rewrite always need one text-model request.
- Text before the cursor, in Settings → recognition and polishing while Text polishing is on (off by default): each dictation sends up to the last 1,000 characters written before the cursor in the current field to the polishing service along with the transcript, so names, terms and misheard words come out right. Nothing is read in password fields, terminals or fields over 6,000 characters, or in a remote desktop window while Work across Macs has another Mac to send to; retries from History do not send it.
- Learn from corrections, at the top of the personal dictionary in Settings (off by default): after out writes a dictation into a field on this Mac, it reads that field again when the next dictation starts, or 30 seconds later, only while the same window still has that field in front and within ten minutes of the write. When a word it wrote was replaced there, the panel asks whether to add the new word to the personal dictionary — a changed word of 2 to 40 characters, not already in the dictionary, not declined before (up to 200 declines are remembered), and only while the dictionary has fewer than 80 entries. Nothing is added without asking, and nothing read is sent anywhere.
- The recording is saved on this Mac first, and the network part streams from the same file while recording, so losing the connection does not stop the recording. A recording is 15 minutes at most; the handshake times out after 12 seconds, recognition after 40 seconds from the commit, and the polishing request after 45 seconds. Offline, OpenAI cannot produce text at once, but the recording and the parts already received are kept.
- A recording finished offline goes into a queue for delayed transcription; once online, it is transcribed when the app is idle, updating History only and never pasting into a field activated later. A recording for This Mac with Text polishing off needs no network at all and retries offline. After a network failure out tries once more after about a minute; if that fails, it waits for the next time the network returns or a manual retry, and never retries endlessly. Authentication, model and similar errors need a fix and then a retry from History; a manual retry uses the service and model selected now; a delayed transcription uses the ones selected when it was recorded. When a complete raw transcript exists, only the text step is retried.
- Audio goes straight to the chosen recognition service, or stays on this Mac when This Mac is chosen; polishing sends the transcript to the chosen polishing service. The screen is never read; the current field's text is read and sent only when you speak an editing command (see "Editing existing text by voice"), is sent along with the polishing request when Text before the cursor is on, and — never sent — is read again on this Mac when Learn from corrections is on. Responses requests set `store: false`; this is not OpenAI's enterprise zero-retention agreement, and the account's data policy still applies on the server.
- The 100 most recent completed texts are kept; pending and failed recordings are not removed by count and can be copied, retried, deleted or cleared in History. They are stored in `~/Library/Application Support/Qingyan/History` (folder 0700, files 0600) as ordinary local files, without extra encryption or cloud sync. PCM audio is 24 kHz / 16-bit / mono, about 2.88 MB a minute. The recording is deleted once transcription and text processing succeed; cancel, delete and clear delete the audio too.
- Audio already written to disk is kept across sleep, quitting or a crash and can be retried later; a buffer not yet written at the very end cannot be guaranteed.

## Protecting system input

- out does not register an input method and does not replace the current keyboard layout; it uses an event monitor and the Accessibility API in the background.
- Fn together with another key does not start dictation; the panel and the capsule are separate, and the recording capsule never takes keyboard focus.
- Dictation does not capture the cursor at the start. The current insertion point is read only when the final text is ready; the app, control, value or selection before and after recording is not compared, and the cursor, field or app may change while recording or processing. With nowhere to write, the text is saved to History and the original app is not reactivated.
- The selection is replaced through Accessibility where possible; apps that do not support it get Cmd+V. The clipboard is then restored, rich text included, and new content copied meanwhile is not overwritten.
- Dictation never sends Return or clicks a send button. Some terminals may treat line breaks in pasted text as Enter; do not use dictation to type unchecked multi-line terminal commands. Type the Clipboard is the exception by design: it types line breaks as Return.
- Dictation does not automatically write into password controls, fields under Secure Keyboard Entry, or custom-drawn fields without Accessibility support (Type the Clipboard does type into password fields); recording to History still works. Secure Keyboard Entry may block global shortcuts; recording can be started from the panel. Recording needs the Microphone permission and a writable disk, but no key or network.
- When only the paste keystroke can be sent, there is no proof the target app handled it; the status reads "Paste sent". The time shown runs from the stop key to the write request, not to the target control finishing drawing.

## Local checks

The Command Line Tools have no XCTest, so the checks use Foundation/AppKit directly, assert public behavior and exit with 1 on failure.

```sh
swift run QingyanChecks
```

They cover Fn combinations, repeated triggers, out-of-order transcription events and final results replacing partial ones, the on-device platform's place among the services (speech and text menus, no key, transcript pieces joined, language names), the output styles (no polishing by default, for an unknown style, or for a recording from before styles, each style's own instructions reach the request, a recording keeps the style it was made in), text before the cursor (sent along only with a polished dictation) and learning from corrections (a replaced word is offered only when the write itself changed), request formats, dictionary limits, refusing cut-off responses, error messages that never echo secrets, rich-text clipboard restore on a real isolated pasteboard and protection of new content. The realtime-socket checks cover the session handshake for both streaming services (fields, the dictionary as context, silence detection that never ends a recording), transcript items joined in spoken order across languages, and the 24-to-16 kHz resampler — identical output however the input is split, a tone inside the band kept, a tone above it removed, and no wrap at full scale. The Shelf checks cover storing and restoring text, images and files across restarts, remembering removals, safe file names, the item limit, cards only for large files, releasing fetched copies by last use, and real sync among three Macs: both directions, multi-frame files identical byte for byte, removal, catching up after being offline, relaying through a third Mac, large-file cards fetched on demand, resuming, fetching one hop away, the notice when the source is offline, and no connection with a wrong code. The voice-editing checks cover the content of the two requests (the first carries only the transcript, the second carries the field's text only as data), splitting the marker, computing the smallest changed span between old and new text (emoji and combining characters included), reading a field on another Mac and writing it back, and that a request without a handshake cannot read the field. The checks of the encrypted channel and trust cover both ends proving their identity, short and long frames round-tripping, forged and replayed frames ending the connection, asking who is there, pairing agreed by both with matching codes, refusal, one-time admission with an old code, another Mac at a known address, the notice to an older version, and per-Mac permissions. The knock checks cover encoding and decoding all 64 combinations, and incomplete, slow and interrupted knocks. The Multiple Macs checks start a real receiver and sender on the loopback address: the original text delivered, long text, no paste with a wrong code, no paste for a connection test, the receiver's failure reported back, a malformed connection not affecting later ones, and a timely error when the receiver is not running. They also verify that, of two receivers, only the one that saw the knock answers, the text reaches only that one, and a Mac with a wrong code or no permission gets no handshake; that a remote desktop's title names a Mac only by whole words and only when no other name fits as well; and that the Mac it names is asked first, the others only when it does not claim the knock, and Macs not reached the last time last. Another real Mac and Tailscale are not involved.
